# 配对假设：私有实践 → 公开回测

> 立此文件的理由（STATE.md D26/D27）：私有来源只能当**假设发生器**，
> 公开语料才是**结论来源**。没有配对回测的私有观察，不许进 `FINDINGS.md`。
> 建立日期：2026-09-11 ｜ 私有来源逐条见 `work/SELF-TRACE.md` 第 8 节

## 规则

每条假设必须写全三样，缺一不成立：**可证伪的形态 / 可计算的口径 / 预期结果**。
"预期"要写清楚"如果假设成立我会看到什么数字，如果不成立我会看到什么数字"——
否则测出来也没法判断。

## H-F1｜章程是被事故逼出来的，不是设计出来的

  S3/S4（moya `CODEX.md` 第 2 次修订标题即事故）
- **可证伪形态**：对同一个仓库的 `AGENTS.md` 取**多次修订**（不是快照），
  看每次修订是否紧跟一次修复类提交（`fix:` / `hotfix` / 事故相关关键词）。
- **公开口径**：需扩抓 —— 对已有 558 份里 star 较高、历史较长的子集，取 `AGENTS.md` 的
  commit 历史（GitHub API），计算「章程修订时间 − 最近一次 fix 提交时间」的间隔分布。
- **预期**：假设成立 → 间隔中位数应在数天内（小于普通提交间隔）；
  不成立 → 间隔与随机分布无差异。
- **状态**：**试点已测（2026-09-11）——提交信息层测不出来，需 diff**，见 `work/charter_history.md`

## H-F2｜章程的寿命长于代码的活跃期

## H-F8｜边界按"路径"划，而不是按"角色"划

- **私有来源**：S8（moya `TRUST.md` 按保护区/协作区/扩展区；`COLLABORATION.md` 按文件名；
  rmas-v3 `CODEX.md` 09-05 版直接对到目录）
- **可证伪形态**：现有 `boundaries` 是个笼统槽位（335/507 命中）。拆成三档重算：
  ①按路径/目录（含 glob）②按角色/负责人 ③按文件清单。
- **公开口径**：对 335 份 `boundaries` 文件跑三档正则，看分布。
- **预期**：成立 → 按路径一档占多数；不成立 → 角色划分占多数。
- **状态**：**已测（2026-09-11）——半成立**，见下

**实测结果**（`work/boundary_style_scan.py`，335 份 boundaries 文件 / 1520 条边界句）：

| 表达方式 | 句级 | 文件级 |
|---|---|---|
| 路径（含 glob） | 377（25%） | 153 份含（50%） |
| 具名文件 | 89（6%） | — |
| 角色 / 负责人 | 35（**2%**） | 25 份含（**8%**） |
| 纯动作禁令（无路径/文件/角色） | 1019（**67%**） | 117 份只有这种（**38%**） |

**判定：**

- **"不是按角色划"——成立**（句级 2%、文件级 8%）。公开章程里的 `role` 指的是**人类维护者**
  （`maintainer-only` / `verified maintainer`），不是"某个 AI 智能体"。
- **"主要按路径划"——不成立**。默认形态是**动作禁令**（67% 句 / 38% 份只有禁令）；
  路径是次强的增强手段（一半的文件至少有一处）。
- 句级与文件级结论不同不矛盾：一份文件通常有多条纯禁令 + 一处路径分节。

**修正后的表述**：边界的默认形态是**"不许做什么"**，不是"哪块归谁"。
区域划分（按路径）是少数团队才做到的进阶形态。

**方法教训（留档，D21 第二次救场）**：第一版线索用裸 `never` / `do not`，
抽验 16 条后发现大量普通英文散文被误判（"never from the stored token"），
边界句虚高到 4292 条；收紧为"否定义动词 + 24 字内的具体动作对象"后才降到 1520 条。

## H-F9｜gotchas 被"外包"给外部知识库（**已测：不成立**）

- **私有来源**：S9（mohu `AGENTS.md` 首条要求先读 `.github/memories/`，正文本身无 gotchas）
- **可证伪形态**：若成立，则「正文无 gotchas」的文件应显著更常指向外部知识载体（**替代关系**）。
- **公开口径**：见 `work/external_ref_scan.py`
- **实测结果（507 份，2026-09-11）**：

  | | 强外包 | 无强外包 | 强外包率 |
  |---|---|---|---|
  | gotchas 缺席（436） | 58 | 378 | **13.3%** |
  | gotchas 在场（71） | 19 | 52 | **26.8%** |

- **判定：证伪**。方向与预期相反——**有 gotchas 的文件反而更可能外包**。
  两者是**增量关系，不是替代关系**。「14% 是量错了对象」这个解释不成立。
- **副产品（可入 FINDINGS）**：发现了一个规则集里没有的槽位 ——
  **15%（77/507）的章程明确指向外部知识载体或规则目录**；
  另 **46%（235 份）存在祈使式转引**（"read/see X.md"）。
  章程普遍是**入口**，不是全集。
- **方法教训（留档）**：第一版口径用「文本里出现任意 `.md` 路径」，命中 442/507 = **87%**，
  抽验 12 条后判定为假阳性机器（README 列表、PR 模板、日志文件名全被算进去）。
  收紧为「祈使转引 + 载体专名」后才可用。**这是 D21 那条纪律的价值实证。**
