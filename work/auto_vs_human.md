# 对照实验：机器生成的 AGENTS.md vs 仓库里人写的那份

**日期**：2026-09-10/11 ｜ **样本**：11 个公开仓库（覆盖 7 种语言）｜ **生成器**：Claude Code（`claude -p`）
**脚本**：`work/auto_vs_human.py`（对比）｜ 原始产物与逐仓库对照在实验目录（不入库）

**要回答的问题**：既然编辑器/Agent 已经能一键生成章程，"章程语料库"还有差异化用处吗？

---

## 方法（不这么做实验就没有意义）

1. `git clone --depth 1` 11 个仓库；然后**把仓库里所有章程文件移出目录**
   （`AGENTS.md` / `CLAUDE.md` / `.cursorrules` / 子目录里的模板章程），
   否则生成器会读到并抄它，结果作废。
2. **删掉 `.git`**。第一轮没删，有两份生成结果里出现了"git status 显示 AGENTS.md 已删除"
   这类线索——虽然模型都说没去历史里取回内容，但这是可避免的泄漏，第二轮起全部移除。
3. 用同一个提示词让生成器「只依据仓库里能找到的东西」写一份 `AGENTS.md`。
4. 把人写的版本放回对照，用本项目的分类器分别打标，并做**抄写检测**（8-gram 重叠）。

**抄写检测结果：0.0% – 0.7%（11 个仓库）**，无抄袭。唯一的非零值来自
"项目是什么"这类必然重合的客观描述。

### 提示词条件（第二个自变量）

| 条件 | 提示词要求 | 样本 |
|---|---|---|
| **p1**（默认 /init 风格） | purpose、structure、build/test/run、conventions、must not | 11 |
| **p2**（点名协作流程） | p1 + contribution workflow（commit 格式 / PR / 分支 / 发布） | 3 |
| **p3**（点名流程 + 坑） | p2 + known pitfalls and gotchas；且**要求"没有证据就明说，不要猜"** | 3 |

## 发现

### 1. 在"写一份能用的章程"这件事上，机器已经超过普通人写的

平均 **5.3 vs 4.6 类**，平均 **7098 vs 4131 字节**，耗时分钟级。
`structure`、`build_test` 双方 11/11；`style` 机器 11/11 而人写只有 6/11；
`overview` 机器 10/11 而人写 3/11。

**"自动生成会替代从零写章程"，在这几块是成立的。**

### 2. 但 11 份机器文件几乎一个模子

骨架统计（11/11）：`AGENTS.md → Project purpose / What this is → Repository layout →
Build·test·run → Conventions → Must not do`。

而**人写的那两份（Whale、nano）也在用同一套 `Repository Guidelines` 骨架**：
语料库里 39 份用这个标题，20 份命中该骨架 ≥4/6 子节，
而 Whale 与 nano 两份人写文件**正文 8-gram 重合 0%**——结构相同、文字各异。

**含义：真正的分界线不是"人 vs 机器"，而是"能从仓库推导出来 vs 推导不出来"。**
机器写和人写在这条线上站在同一边。

### 3. 决定性差异：机器 0/11 写协作流程——原因是提示词，不是能力

`workflow`：人写 **8/11**，机器 **0/11**，干净得可疑，所以逐份查了原文：
机器文件里的 "commit" 全是顺带提及（某配置文件要提交、构建期注入的 commit 串），
**没有一份写了提交/PR/分支/发布流程**。

于是做了 p2 对照（点名要流程）——**3/3 立刻写出来了**：

| 仓库 | p1（默认） | p2（点名流程） | p3（再点名坑） |
|---|---|---|---|
| ts2 | workflow 0 | **1** | 1 |
| Whale | workflow 0 | **3** | 3 |
| minisim | workflow 0 | **2** | 2 |

**结论：机器漏的不是"仓库里有的信息"，是"提示词没点到的槽位"。**
自动化的短板不在知识，在**提问**。

### 4. 我上一轮的判断错了：机器写得出"坑"

上一轮我说"机器补不上只有经历过才知道的内容"。p3 把这一条推翻了——
点名要 gotchas 后，3/3 都写出来了，而且内容是**真知识**：

- ts2：`--codex` 模式已被封锁（`src/index.ts` 直接报错并重定向），旧模式已弃用
- Whale：**README 说的 `whale ask` / `--headless` 根本不存在**，真实入口是 `whale exec --mode ask`
- minisim：`UserDefaults` 里有个**拼错的键名 `preferedTerminal`**（不是 preferred），改动时别"顺手修正"

这些都是读代码/读文档才能发现的非显然信息，正是人写章程里那种"别踩这个"的内容。

**修正后的结论**：机器能产出的是**"可从当前仓库读出来"的坑**（文档与代码不一致、
弃用路径、平台限制、拼写陷阱）。它产不出的，是我在样本里也没找到人去写的另一类：
**"曾经出过事"的历史**——那次 CI 为什么挂、上个季度为什么回滚、
某个依赖为什么被钉死在旧版本。

### 5. 双方共同缺席的仍然是同一块

`gotchas`：人写 **0/11**，机器 **0/11**（语料库整体也只有 14%，九类最低）。
`agent_meta`：人写 1/11，机器 0/11。

区别在于：机器**点名就能补上**（见发现 4），而人写的这 11 份里**根本没人想到要写**。
这可能是本数据集最有意思的一条：**不是写不出，是没人想起来写。**

### 6. 方法学副产品：分类器对标题措辞的依赖被实证了

机器"漏掉"的 `environment` 有一半是**分类口径**造成的：
人写标题是 `Security & Configuration Tips`（命中 `config`），
机器把同类内容写在 `Do not` 小节里（判成 `boundaries`）。内容没差那么多，是措辞不同。
v0.1.1 补的是同义词，补不了这个结构性问题。

## 不能从这里推出什么

- **n=11，一个生成器（Claude Code），一个模型，一个提示词家族。**
  这不是"自动生成质量评测"，是**覆盖面结构的对照**。
- 生成器只读仓库，没读 issue / PR 历史 / CI 日志。给它这些证据源，
  发现 4 里"读不出来的坑"未必还读不出来。
- 类别差异中仍有一部分是分类器口径（见发现 6），不能全读成内容差异。

## 对项目定位的含义

1. "章程模板/最佳实践清单"这条线不要站——会被免费吃掉（发现 1、2）。
2. **真正的差异点是"该问什么"**：机器的覆盖面由提示词形状决定（发现 3），
   而"该问哪些问题"的答案，正好是 558 份人写章程的分布。这给 `compare` 找到了
   更硬的产品形态：不只是"你缺哪几类"，而是**生成时的检查清单**。
3. 数据集不再是"人写的章程集合"，而是**"非自动可推导内容的分布"**——
   而这需要一个 **人写/机器写判定字段**（v0.2）。自动化越普及，这个字段越关键，
   目前还没有别人需要解这个问题。
4. 值得下一步测的：**语料库里的 `gotchas`，有多少是"能从当前仓库读出来"的，
   有多少是"事故/历史"类**。前者机器点名就能补，后者才是真正的空白。
