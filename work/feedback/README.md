# 反馈入口（错误标本的收容所）

**为什么有这个目录**：`SHARE.md` 里写了"错标比漏标伤害大得多"，但在此之前**没有任何地方接住这些反馈**——
评论一多就散在知乎/OSC/issue 里，下一次改分类法时只能凭记忆。
这个目录就是把"真实被标错的样本"变成可检索、可复算的清单。

## 怎么记

一条反馈 = 表里一行。字段：

| 字段 | 说明 |
|---|---|
| 渠道 | 知乎 / 开源中国 / HN / Reddit / GitHub issue / 私信 |
| 出处 | 评论或 issue 的 URL（**没有 URL 的，写"微信/口头"并注明日期**） |
| 原文件 | 仓库 `owner/repo` + 路径；能拿到内容就存到 `work/feedback/samples/` |
| 被标成 | 我们的规则给了什么（类别名） |
| 实际是 | 反馈者认为应该是什么 |
| 类型 | 漏标 / 错标 / 口径争议 / 关键词缺失 / 其它 |
| 处理 | 进 v0.3 清单 / 已驳回（附理由）/ 待定 |

## 三条纪律

1. **凡"错标"必进清单**：错标污染统计，优先级最高；漏标只损失召回。
2. **凡"关键词缺失"要附原文片段**：否则改不动规则（关键词法只能识别写进词表的表达）。
3. **凡"驳回"必写理由**：驳回也是结论，别让它消失——`LIMITATIONS.md` 里那些"刻意的失败方向"就是这么来的。
