发布前确认（登录后第一眼要看的两件事）
1. 博客编辑器是否支持 Markdown 源码模式——不支持就照下面清单点样式
2. 新账号首发是否进"待审核"——发完在「我的博客」看状态

排版清单
1. 点「标题」样式（5 处）：这是什么 ／ 三条值得看的 ／ 工具 ／ 安装 ／ 边界与反馈
2. 「三条值得看的」里的 1/2/3 是编号列表
3. 点「代码块」/引用样式（4 处）：agent-charters compare 你的AGENTS.md ／ 两行 pip install ／ 仓库与镜像两行
4. 分类/标签建议：开源项目、人工智能、程序开发
5. 链接只留 GitHub + Gitee 两个（《社区规范》反对恶意营销导流）
6. 同日不要再在「动弹」「问答」里发同一链接
7. 发完用无痕窗口确认公开可见

本文件由 make_paste.py 从 SHARE.md §4.5 生成：改文案请改 SHARE.md，然后重新生成，不要只改这里。

================ 发布后补充评论（发出来就贴，别等人问） ================

补几条正文没展开的：

1）分母是 511，不是 558。558 是抓取总数，其中 40 份是近乎空的占位文件、7 份正文只有一句"见 CLAUDE.md"，
   这两类都排除在百分比之外。
2）数据集两种格式（parquet / jsonl）都在 Release 里；标注没有用模型，每行带 file_sha + 采集日期 +
   抽取器/规则集版本，任何人可复算。
3）工具装上就能用：pip install git+https://gitee.com/janzong/agent-charters
   然后 agent-charters compare 你的AGENTS.md，看自己哪几类一个字没写。
4）已知最大的缺陷：中文样本只有 5%（26/511），按语言做的任何对比都缺统计效力；覆盖率是下界。
5）有被标错的样本直接回帖。错标比漏标伤害大得多，这类反馈我会直接进下一版分类法修订。
