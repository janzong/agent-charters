# 「扩展文件类型」的可行性实测（2026-09-15，**只读探测**）

**为什么测这个**：`STATE.md` §5「第三优先」挂着一条 ⏳「扩展文件类型（`CLAUDE.md` / `.cursorrules` /
`copilot-instructions.md`）」，但**从来没人量过它到底有多大增量**。要不要做、做哪几种、值不值得开新数据集版本，
都卡在这一个数上。这轮把它量出来。

**方法**：对语料库那 558 个仓库，各拉一次 GitHub trees API（`GET /repos/{repo}/git/trees/HEAD?recursive=1`，
一次拿全树，比逐文件探测省 6 倍请求），在本地数同类文件。脚本 `work/audit/filetype_probe.py`
（**只读**；产物落 `data/cache/trees/*.json`，在 `.gitignore` 里，重跑不打 API）。

**样本口径（必读）**：本轮**成功 482 / 558（86%）**——api.github.com 这条链路经代理后抖动，
剩下 76 个吃 `IncompleteRead`。**失败不写缓存**（第一版把失败记账，导致 204 个仓库被永久跳过，已修），
所以 `--no-fetch` 出的是当前样本，重跑一次即可补齐。下面所有百分比都是**这批 482 个仓库**里的比例。

## 结果

| 文件类型 | 有它的仓库 | 占比 | 文件数 | 其中符号链接 | 与根 `AGENTS.md` 逐字节相同 |
|---|---|---|---|---|---|
| `AGENTS.md`（现有语料，对照） | 482 | 100% | **1650** | 52 | 420 |
| `CLAUDE.md` | 285 | **59.1%** | **715** | **192** | 7 |
| `.github/copilot-instructions.md` | 51 | 10.6% | 51 | 5 | 0 |
| `GEMINI.md` | 37 | 7.7% | 109 | 4 | 2 |
| `.cursor/rules/*.mdc` | 27 | 5.6% | 108 | 1 | 0 |
| `.cursorrules`（旧式） | 8 | 1.7% | 10 | 4 | 0 |
| `.windsurfrules` / `.windsurf/rules` | 7 | 1.5% | 8 | 1 | 0 |
| `.clinerules` | 5 | 1.0% | 17 | 0 | 0 |
| `.aider*` / `.rules` | 各 1 | 0.2% | 1 / 1 | 0 | 0 |

**含 ≥2 类同类文件的仓库：310 个（64%）**；其中**没有** `AGENTS.md` 的：**0 个**。

## 四条结论

1. **同类文件是"同一批仓库的第二份文档"，不是"新仓库"。** 482 份里有 0 份是"只有 `CLAUDE.md` 没有
   `AGENTS.md`"——因为样本本来就是**按"有 `AGENTS.md`"选的**。想要新仓库，得单独做一次
   "搜 `CLAUDE.md` 但没有 `AGENTS.md`"的发现（那是另一个口径、也是另一个问题）。
2. **`CLAUDE.md` 的增量足够大**：285 个仓库（59.1%）有它，总 715 个文件；扣掉 **192 个符号链接**
   与 7 个逐字节相同，≈**516 个不同的 `CLAUDE.md`**——与现有实质语料（516 份）**同一量级**。
   注意它们**更短**（第一版抽样里中位 1.7 KB vs `AGENTS.md` 3.8 KB），像是"快速定位"文档。
3. **去重是必须先做的功课**：`CLAUDE.md` 有 **27% 是符号链接**（192/715，多半指向 `AGENTS.md`），
   `AGENTS.md` 自己也有 29% 是根文件的副本/链接（420 相同的 1650 里）——现有管线**不解析符号链接**，
   直接扩类型会把重复内容灌进语料。第一步得是"解析链接 + 按 blob sha 去重"（trees API 的 `mode=120000`
   就是符号链接，`sha` 可直接与数据集现有 `file_sha` 比对，**逐字节级**判重，不用下正文）。
4. **"跨文件一致性检测"这条启发有真实底座**：310 个仓库有 ≥2 类同类文件
   （`STATE.md` §5「其它方向③：同一仓库 `AGENTS.md` 与 `CLAUDE.md` 是否互相矛盾」）。
   这可能是比"把 `CLAUDE.md` 塞进同一个九类统计"更值钱的方向——同一仓库两份文档的**分歧**本身就是数据。

## 给人裁定的三个选项（数字都在上面）

1. **不做**：现状不变。理由：0 个新仓库 + 需要先写符号链接/去重逻辑，成本落在"零增量"的仓位上。
   （但**跨文件一致性**这条线会一起放弃。）
2. **只做 `CLAUDE.md` 的"第二文档"**：新采 ~516 份、标注同一套九类，数据集升 **v0.6**（`D18`：不静默替换
   已发布资产 ⇒ 必须新切一版）。收益：同一批仓库里"两份文档写的一样不一样"变成可算的。
3. **做"扩展类型 + 跨文件一致性"**：在 2 的基础上把 310 个多文件仓库的**分歧**做成一个独立产物
   （不需要把 `.cursor/rules` 那 108 个 `.mdc` 也标九类——它们太短、格式也不同）。
   代价最大，但也是唯一一个**只有多文件语料才能做**的东西。

**下一步（无论选哪个都要先做的一件）**：把符号链接解析 + blob sha 去重做进发现管线，
并用 `--limit` 在 20 个仓库上跑一遍验证去重逻辑（`data/cache/` 已缓存 482 棵树，重跑零 API 成本）。
