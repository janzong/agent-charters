## 二、发现 44 扩样｜形容词/泛名词作标题词

补两例，与 `Import Organization` 同族——**短名词/形容词在标题里时，指代由相邻词决定**：

```
mini-kode     ### Import Organization        → organization 命中，实为 style
apidash       ## Standard Commands           → standard 命中，实为 build_test
camel         ## Merge Requirements          → requirement 命中，实为 workflow/build_test
```

⇒ v0.1.8 的通用修法建议：给这类**泛名词**（`organization` / `standard` / `requirement` / `rule` / `pattern` /
`version` / `tool` / `review` / `style`）加"**相邻词否决表**"——
标题里若出现 `import/testing/merge/architecture/commit/…` 这类领域词，泛名词不再单独决定类别。

## 三、发现 46｜`heading:rule` 的泛化误伤（43 / 222）

`rule` 是全库命中最多的边界词：**222 个标题全部拿到 boundaries**，其中 **43 个标题里另有领域词**
（`Rules for Testing`、`Rules for TypeScript`、`Testing Rules`、`Documentation Rules`、`Architecture (Non-Obvious Rules)`、
`Code Shape Rules (all languages)`、`Product And Security Rules`…）——这些节的归属应由领域词决定
（testing→build_test、TypeScript→style、architecture→structure），不该一律记成禁令。

- 与发现 37 合看，`boundaries` 的两条供给线是：
  ①**标题里的 `rule`/`never`/`constraint`**（222 + …）；
  ②**正文里的 `must not`/`never commit`**（345 个章节、21 份文件独撑）。
  两条都偏"**句式触发**"而非"主题判定"。
- ⇒ 不建议删 `rule`（222 个里 179 个是对的），建议只加**领域词否决**（同发现 44 的修法）。
- ⚠️ 另记一条正面观察：**`rules` 型标题是中文语料之外最可靠的禁令信号**，删它会让 boundaries 掉一大截，
  这个类的 67.1% 覆盖率里有一部分就是这么来的——v0.1.8 出报告时要把"句法型覆盖率"讲清楚。
