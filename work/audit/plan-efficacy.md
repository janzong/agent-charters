# 章程有效性实验：预登记设计稿 v0（2026-09-18，**待人裁定，未跑**）

**要回答的问题**：`AGENTS.md` 这类章程**真的帮到干活了吗**？
到本文为止，本项目所有产出都停在**描述**（有多少、长什么样、在不在扩散），
**"有没有用"一次都没测过**。这是唯一一个从 0 到 1 剩下的方向。

**性质**：先设计、后执行。**三个岔路必须由人裁定**（见 §2），裁定前不跑任何实验、不动任何数据。

---

## 1. 先把"实用性"的两种读法分开

| 读法 | 是什么 | 本项目怎么处置 |
|---|---|---|
| ① **工具对外更好用**（加命令、加格式、加输出） | 产品功能 | ❌ **D42 已否**（不再加功能/维度）；且判据 5/6 说明**没人用**，加功能无用 |
| ② **章程真的帮到干活** | 机制的因果证据 | ✅ **这才是本条"实用性"的本体**，也是本设计要测的 |

**一个必须说清的区别**：本实验能回答"**章程有没有用**"，
**不能**补上判据 5/6 缺的"**非作者的外部使用者**"——那是两回事，别混。
（变体 D 是唯一能沾到外部性的形态，见 §4。）

## 2. 三个岔路（**你定，我不替你定**）

### 岔路 1｜什么算"有效"？（三档，从便宜到贵）

| 档 | 定义 | 判定成本 | 客观性 |
|---|---|---|---|
| **L1 机械可判** | 产出是否违反章程里**明写**的禁令/命令（如"不动 `data/raw`"、提交信息用 conventional commits） | 免费（脚本） | 高 |
| **L2 人工判可用** | 产出被盲判为"可用/不可用" | 3–5 分钟/份 | 中（主观） |
| **L3 返工轮数** | 发起方要求返工的次数 | 免费（读会话/提交记录） | 中高 |

**我的建议**：**L1 主、L3 辅、L2 抽子集校验**。理由：L1 客观且可自动化，L3 零成本，
L2 最贵但只有它能抓住"没违反规则但就是不好用"。

### 岔路 2｜谁当判定者？

- (a) **你**（最可信，最贵）；(b) **另一个模型的 agent**（便宜，但有噪声）；
- (c) **两者都判，算一致率**。

**我的建议**：(c)。并且**预登记一条"实验作废"条件**：两人一致率 **<70%** ⇒ 判定本身不可靠，
实验结果作废（不算负结果）。这条很重要——判不准的实验比没实验更坏。

### 岔路 3｜愿付多少人力？

- **0 小时** ⇒ 只开 §5 的零成本仪表轨
- **1.5–2 小时** ⇒ L2 子集（约 24 份）盲判，完整实验
- **>5 小时** ⇒ 加变体 D（外部性最强，周期不可控）

## 3. 设计 v0：前瞻型随机对照（三臂）

### 3.1 单元与入选条件

- **任务**：8–12 个**真实小改动**（不造题），从机队待办里挑
- **入选条件（硬）**：该仓库章程里**至少有一条明写规则适用于这个任务**——
  否则"给不给章程"没区别，测的是空气
- 每个任务记下"哪几条规则适用"（判定 M1 就靠它）

### 3.2 三臂（**C2 是关键，别省**）

| 臂 | 提示里附带的内容 |
|---|---|
| **T（treatment）** | 该仓库的章程全文 |
| **C1（no-info）** | 什么都不附 |
| **C2（placebo）** | **等长的无关文档**（如 README 摘要，字数与章程对齐） |

**为什么必须有 C2**：没有它，"T 比 C1 好"可能只是"**多给了上下文**"这个一般效应，
不是章程的功劳。C2 把"多给上下文"剥掉，剩下的才是章程本身的增量。
（这条是设计里最容易省、也最不该省的一步。）

- 其余条件完全相同：**同模型、同提示模板、同起点 commit、同工具权限**
- 每臂跑 **K=3** 次 → 单元数 8×3×3 = **72**（12 任务则 108）

### 3.3 预登记判据（先说好什么结果说明什么）

- **主判据**：M1 违规率 `T vs C2` 差 **≥20pp** 且 bootstrap CI 不跨 0 ⇒ **有效**
- **次判据**：M3 返工轮数同向差 ≥0.5 轮 ⇒ 支持
- **负结论也预登记**：`T vs C2` 差 **<10pp** ⇒ **"在 8–12 个任务上测不出效应"**，
  照样发布，并据此**改项目对外说法**（当前"章程有用"是**未经检验的主张**）
- **作废条件**：判者一致率 <70%（§2 岔路 2）

⚠️ 若 `T > C1` 但 `T ≈ C2` ⇒ 结论是"**多给上下文有用，章程本身没有额外用**"——
这也是个真实且重要的结论，不许事后改口径。

### 3.4 成本

- 自动侧：脚本 + 约 72–108 次 agent 跑（机队可承担；**全是本地模型/自有 key，不产生外部费用**）
- 人工侧：L2 子集盲判，约 **1.5–2 小时**（你）

## 4. 变体 D（外部性最强，周期不可控，**要不要留作后手你定**）

给**别人维护的、带章程的**开源仓（从 558 语料里挑）提一个真实小改动，
让**维护者的 CI / review** 当判定者。
- 优点：判定者**不是作者**，沾到判据 5/6 的边
- 缺点：周期不可控（等 merge）、章程不是我们写的（**这恰恰是优点**）、n 极小

---

## 5. 零成本并行轨：机队仪表（**已开，见 §9**）

在**真实任务流**里记账，回答"**章程里明写的规则，实际被遵守多少**"（合规率 / ceiling check）。
跑 1–2 个月 → 决定值不值得做正式三臂对照（档位见 §9.1）。

⚠️ **与 D42 的边界**：这是**机队工作流的记录**，不是数据集/面板的字段（不破"不加维度"）。

## 6. 已知弱点（预登记，不事后补理由）

1. **n 小**，效应可能测不出——所以负结论也进了预登记。
2. **混杂**：任务难度、模型、仓库熟悉度。随机化能压一部分，压不干净。
3. **章程是我们自己写的** ⇒ "T 臂"隐含"看作者自己写的东西更顺"的可能；C2 只能剥掉"长度"这一层。
   ⇒ **不要把这个实验结果当成判据 5/6 的答案**。
4. **判定主观**（已用一致率作废条件兜底）。
5. **"有规则" ≠ "规则对"**：本实验测"章程有没有被遵守、产出好不好"，
   **不测**"章程写得好不好"。后者是另一个实验。

## 9. 仪表轨（2026-09-18 上线，同日晚调整过一次主指标）

### 9.1 为什么主指标是「合规率」，不是「有/无章程的差异」

**原设计的硬伤**：我一开始想让仪表轨当"天然实验"——有的仓有章程、有的没有，拿它当对照组。
**但机队只在自己那几个仓上干活，而这些仓几乎都有章程**（rmas-v3 / agent-charters 都有，
Codex 还会自动加载 `AGENTS.md`）⇒ **"无章程"那一臂根本没有样本**，靠它做对照只会得到一张空表。
这条不修，攒两个月也是白攒。

**改成的量**：**写在章程里的规则，实际被遵守的比例（合规率）**。它不需要对照组、当天就能出数，
而且正好是决定"值不值得花人力做正式实验"的那个量：

| 合规率 | 含义 | 动作 |
|---|---|---|
| **≥95%** | 天花板效应：T/C1/C2 测不出东西 | **不做正式实验**（省下那 1.5–2 小时） |
| **70–95%** | 有空间 | **值得做** |
| **<70%** | 问题不是"有没有用"而是"**根本没被执行**" | 换方向（执行机制），别做有效性实验 |

`--charter yes/no` 字段**保留**（不花钱，万一将来真遇到无章程的仓），但**不再依赖它**。

### 9.2 规则登记表（一次性成本，换掉每任务现读章程）

`work/efficacy-rules.jsonl`：每个仓库一份"**可机判**规则"清单（编号 + 原文 + 怎么判）。
已登记 **14 条**：`agent-charters` 9 条（ac1–ac9）、`rmas-v3` 5 条（rm1–rm5）。
之后每个任务只填编号，不用再翻章程：

```bash
.venv/bin/python work/efficacy_log.py rules                              # 看登记表
.venv/bin/python work/efficacy_log.py add --repo agent-charters \
    --task "分母研究" --rules ac1,ac2,ac4,ac7 --violated ac4,ac7 --rework 0
```

**没登记的仓**回退到自由文本 `--applicable "…;…"`。没有适用规则的任务写 `--rules none`
（这一行照样记，它说明"这个任务的适用规则数是 0"，报告里会显示覆盖率）。

### 9.3 字段口径（写死，别漂）

| 字段 | 含义 | 容易搞错的地方 |
|---|---|---|
| `--rules` | 登记表里**明写且适用于本任务**的规则编号 | 判定 M1 **只认这些**；不适用的一律不算 |
| `--violated` | **产出**实际违反的（必须是适用集合子集，脚本会拦） | 不是"章程没写好" |
| `--rework` | 发起方要求返工的轮数（0 = 一次过） | L3，零成本 |
| `--charter` | 任务运行时上下文里**确实有**该仓章程吗 | 是"**真的进了上下文**"，不是"仓库里有这个文件" |

### 9.4 执行点（**没有它这台仪器就是摆设**）

写进了 **`~/.codex/AGENTS.md`**（每次会话自动加载的全局约定）："每完成一个真实任务记一行"。
只写在项目文档里没用——文档不会自己进上下文。

### 9.5 两条纪律

1. **不要回填历史任务**。回填必然带着"已经知道结果"的偏差。表从 **2026-09-18** 开始。
2. **每个真实任务都要记，不许挑**。挑着记的数据比没有数据更坏——它会把"我认真记的那几次"当成全体。

### 9.6 这个轨能读什么、不能读什么

- ✅ 能读：**离天花板有多远** ⇒ 值不值得做正式三臂对照
- ⚠️ 分母是"规则条目数"，同一条规则在不同任务上被当独立观察 ⇒ **CI 偏乐观**，只当参考
- ❌ 不能读：**因果**。谁有章程和任务类型相关，`report` 每次都把这句话打出来
- ❌ 不能读：**章程写得好不好**。这里只测"写了的有没有被遵守"

### 9.7 上线当天就有真实数据

头两行记的是**我自己**今天干的活，两行**都有违规**：
①写了未声明的 `requests` 依赖（**同日改回标准库** `http.client` keep-alive）；
②先提交后跑 pytest。规矩是给智能体定的、智能体自己先犯——这恰好说明
"写了章程不等于会被遵守"是**真现象而不是假想问题**。若头两行全是 0 违规，这台仪器才该被怀疑。
