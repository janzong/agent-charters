## 二、发现 42｜撤 `quick reference` 的副作用（发现 2 / 8 的合流）

v0.1.7 按裁决 2 撤掉了 `start here` / `quick start` / `quick reference` 三个容器型标题词
（当时实测：独撑 7/3/10 份，全错或 9 错——**撤是对的**）。但本批撞到它的副作用：

- `grok-cli` 的**唯一** build/test 内容是 `### Quick reference` 下的一张表（`bun install` / `bun run typecheck` / `bun run build`），
  撤词后**没有任何通道接手** ⇒ 整份文件掉 build_test。
- 根因不是"撤错了"，而是**正文弱信号通道缺英文模式**（发现 8）：中文正文有 `运行/构建/测试` 之类模式，
  英文正文一条都没有，所以一旦标题通道失灵就无处兜底。
- ⇒ v0.1.8 补英文正文命令模式时，**这张"Action | Command"两列表必须能命中**（表格单元格里出现
  `npm/pnpm/bun/yarn run build|test|lint|typecheck`、`cargo build`、`go test`、`pytest` 等）。

## 三、发现 43｜"注入式规则块"整块无标签（新形态）

`ai-website-cloner-template` 顶部有一个 Next.js 自动注入的 HTML 注释块：

```
<!-- BEGIN:nextjs-agent-rules -->
# This is NOT the Next.js you know
… APIs, conventions, and file structure may all differ from your training data …
Read the relevant guide in node_modules/next/dist/docs/ before writing any code.
<!-- END:nextjs-agent-rules -->
```

- 这是框架生成的**给 agent 的规则块**，语义上明确属 agent_meta（"你的训练数据里的 Next.js 不是这个"），
  整块 0 命中。
- **可期待的规模**：凡用 Next.js 16 的仓库都会自动生成这个文件；本语料库目前只有 1 例
  （因为采集时 Next.js 16 还很新），但这是**会自己长大的形态**——值得在 v0.1.8 里给一条最窄的模式
  （如 `\bdiffers? from your training data\b` → agent_meta，这是该块的固定句式）。
- ⚠️ 同时注意：`HTML 注释里的 `# 标题` 仍会被 `split_sections` 当标题`（本文件就多出一个 h1）。
  这条行为本身**不算错**（注释块里的标题确实是内容），但要在 v0.1.8 的重编号里记一笔。

## 四、发现 44｜`heading:organization` → structure 命中 "Import Organization"

`mini-kode` 的 `### Import Organization`（讲 import 分三组、组间空行、组内字典序）被判 structure。
与发现 9（`tool`）、发现 30（`version`）、发现 38（`style`）同族：**短名词作为章节词时，
它的"指什么"由后一个词决定，不由它自己决定**。
建议：`organization` 只在 `repo/module/code organization` 这类形态下算 structure，
`import organization` 归 style。
