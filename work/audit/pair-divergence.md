# 同一仓库两份章程的「分歧」实测（2026-09-15，**最小验证 / 只读**）

**验的是什么**：上一轮我建议"不选选项 2（把 `CLAUDE.md` 再标一遍九类），改做选项 3（跨文件一致性产物）"，
理由是"同一仓库两份文档写的不一样，这个量没人量过，而且比再加 516 份语料值钱"。**这是直觉，不是数据。**
这份记录就是去验它——结果**把那个建议打掉了**，所以照本项目的规矩自我更正 + 留档。

**方法与样本**（脚本 `work/audit/pair_divergence.py`，正文缓存 `data/cache/blobs/`，都不进库）：

- 从 482 棵已缓存的仓库树里取"根级 `AGENTS.md` + 根级 `CLAUDE.md`、非符号链接、blob sha 不同"的**成对**：
  共 **174 对**；
- 抽样 **40 对**下正文（按尺寸比分档：近似 45% / 差一截 33% / 极端 22%），做三件事：
  ① 行级 `difflib` 相似度 + 两边各自的**独有行数**；② 九类覆盖对照；③ **槽位对照**——
  包管理器 / 测试 / 格式化 / lint / 合并策略 / 提交规范 / CI / 锁文件 八个"只能有一种做法"的选择位，
  **同一互斥族内两边取值不同才算冲突**（"一边多写了个 `pip`"不算）。

## 结果一：40 对里**真冲突只有 1 条**

分类（先认出"其中一份不携带信息"，否则会把分歧估高——第一版就是这么错的）：

| 形态 | 对数 | 占比 |
|---|---|---|
| **指针 / 空壳 / 单边子集**（其中一份 <400B 或独有 ≤3 行） | 15 | **38%** |
| 近重复（相似度 ≥0.8） | 1 | 2% |
| 一边是另一边的摘录 | 1 | 2% |
| **真分叉**（两边都有 ≥10 行独有内容） | 23 | **58%** |

**唯一那条真冲突**：`Tencent/AI-Infra-Guard` —— `AGENTS.md` 教 `pip install -r AIG-PromptSecurity/requirements.txt`，
而 `CLAUDE.md` 写这个子项目 "managed with `uv`" 且用的是 `uv run …`。**这是"过期命令"那一类**：
照 `AGENTS.md` 做的人会白撞一次。**1 / 40 = 2.5%**。

## 结果二：174 对全量的"空壳率"（不用下正文，树里有尺寸）

| 指标 | 数量 | 占比 |
|---|---|---|
| **其中一边 <400B**（指针/空壳嫌疑） | 86 | **49%** |
| 其中一边 <100B（基本就是 `@./AGENTS.md` 那种） | 63 | **36%** |
| 尺寸接近（≤1.5×） | 36 | 21% |
| 尺寸差 >10× | 93 | 53% |

（真实例子：`modelcontextprotocol/inspector` 的 `CLAUDE.md` 全文 = `@./AGENTS.md`，13 字节；
`JuliusBrussee/caveman` 的 `AGENTS.md` 只有 734B，写着 "Read `CLAUDE.md` before repository work"，九类 **0/9**，
而 `CLAUDE.md` 38KB、6/9。）

## 结论：**选项 3 原样不成立**，但冒出一件更小、更该做的事

1. **"两份文档互相矛盾"这个卖点是假的**：40 对里 1 条（2.5%）。原因也清楚——两份**通常不是竞品**：
   58% 是真分叉，但相似度常常接近 0（`browser-use`：`AGENTS.md` 独有 527 行、`CLAUDE.md` 独有 109 行），
   也就是"**为不同工具/不同用途写的两份不同文档**"，不是"同一套规则的两个版本"。矛盾检测没什么可检测的。
2. **选项 2 的价值也被这份数据削弱**：38% 的成对里有一份是空壳/指针 ⇒ "CLAUDE.md 能带来 ≈516 份新文档"
   这个估算要打折，而且打折的部分正是最容易看见的那部分（`@./AGENTS.md`、`Read CLAUDE.md`）。
3. **真正普遍、且直接砸到我们自己头上的，是"一半的成对里有一份是指针/空壳"**：
   - 我们的 **GitHub Action / `compare` 是单文件判定的**——对着一个 10B 的 `CLAUDE.md` 或一个 734B 的
     routing-stub `AGENTS.md`，它会报 **0/9**，用户看到的是"你的章程很空"这种**错误结论**；
   - 这正是"用户跑一次就不再用"的那类体验，而修它的成本很低：**识别并跟随指针**
     （`@./AGENTS.md`、`Read CLAUDE.md`、以及 `mode=120000` 的符号链接），或者在结果里**明说**"这份文件是指针，
     真正的规则在 X"。现有的 `is_pointer` 反证闸已经是半个能力了。

**所以改建议为**：先做 **"指针识别 / 跟随"**（工具行为，不动数据、不动规则集，能单独发一个 0.4.x），
把选项 2 / 3 都推后——等真有读者跑 Action 撞上这个坑再谈语料扩展，比先建一整套双文档管线便宜得多。

**这次验证的边界**：①40 对是**分档抽样**，不是随机抽样（偏向"近似"和"极端"，因为想看矛盾与指针两端）；
②"真冲突"只在 8 个槽位上判，别的矛盾形态（比如两处对同一件事给相反的禁令）**没测**；
③槽位是按正则认的，会有漏判（判成"没冲突"比判成"有冲突"更可能）。
