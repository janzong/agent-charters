## 二、四类根因（都指向"标题词表多义词"，与 v0.1.6 已修的 4 处同源）

### 发现 1｜`heading:usage` → build_test：4 份里 3 份是错的

全库**只靠这一个词**撑起 build_test 的有 4 份（另有 16 份有别的证据，不受影响）。

| 仓库 | 段落标题 | 实际内容 | 应该是什么 |
|---|---|---|---|
| `google/benchmark` | `AI usage` | AI 使用政策 | agent_meta + boundaries |
| `iflytek/astron-agent` | `Context7 Usage Rules` | MCP 工具使用规定 | agent_meta |
| `kupzed/catatz` | `Color Usage Rules` | 颜色令牌使用规范 | style |
| `Sahir619/fable-method` | `Usage` | 斜杠命令用法 | build_test（**唯一站得住的**） |

→ 判据：`usage` 只在标题**整体就是"用法"**时才算 build_test；带限定语（AI / Color / Context7 / Token）时语义已变。

### 发现 2｜`heading:start here` → overview：7 份**全是错的**（0/7）

`start here` 在全库只贡献过 7 份 overview，且**没有一份**是和其他证据一起出现的——我逐份读了那 7 个章节：

| 仓库 | `Start Here` 段的实际内容 |
|---|---|
| `Awarexone/Agentic-Bug-Hunter` | 一段 bash 代码块 |
| `NanmiCoder/cc-haha` | 改代码前的 git/纪律要求 |
| `ayghri/i-have-adhd` | 按顺序读 README/INSTALL/SKILL 的阅读顺序 |
| `fallow-rs/fallow` | `docs/development/*.md` 文档地图 |
| `openclaw/Peekaboo` | 先读外部脚本、submodule 更新纪律 |
| `Kevandrew/sophia` | 6 个 `docs/*.md` 指针 |
| `botiverse/hands` | 读本文件+CONTRIBUTING、验 gh/ssh 环境 |

→ 结论：`Start Here` 是**导航/流程**段，不是项目概览；overview 词表里收它是纯假阳性。
→ 同类：`heading:quick start` 也只贡献过 3 份，**3 份全是命令行块**（`CLI quick start` / OmniRoute 的 npm install+dev+build / beads 的 `bd ready --json`），同样该撤。

### 发现 3｜`heading:dependency` → environment：7 份里 3 份是错的

| 仓库 | 段落 | 实际内容 | 应该是什么 |
|---|---|---|---|
| `YishenTu/claudian` | `Dependency Direction` | `A -> B` 表示 A 可 import B（模块边界） | structure |
| `charmbracelet/crush` | `Key Dependency Roles` | 各依赖库扮演什么角色、用在哪 | structure |
| `langchain-ai/langgraph` | `Dependency map` | 下游库依赖拓扑图 | structure |
| `triggerdotdev/trigger.dev` | `Dependency Pinning` | 版本必须钉死 | environment ✓ |
| `AcidicSoil/lms-llmsTxt` | `Dependency Security Posture Policy` | 供应链安全姿态 | environment ✓ |
| `hotosm/ui` | `Dependency and Versioning Policy` | 依赖与版本策略 | environment ✓ |
| `owncloud/notes` | `Dependency Management` | Dependabot 维护 | environment ✓ |

→ 判据：依赖的**管理/版本/安全**是 environment（词表定义里就有"依赖"）；依赖的**拓扑/方向/角色**是架构，属 structure。

### 发现 4｜`heading:module` → structure：2 份全是错的

- `stablyai/orca` `## File and Module Naming` → 命名规范 = **style**（"naming" 本就该命中 style）
- `thunderbird/thunderbolt` `## Module scope freezes the locale` → i18n 陷阱 = **gotchas**

→ 判据：裸词 `module` 太泛；`Adding a new module`（流程）、`Module scope ...`（坑）、`File and Module Naming`（风格）三类都不是结构。

### 附带：两个通道性缺口（不是多义词，是词表没覆盖）

1. **workflow 不认"编号步骤型 how-to"**：`## Adding a new core module` 四步、`## Adding a new platform` 三步，两条都没命中 workflow——workflow 词表本质只有 git/PR/发布词（branch/commit/PR/review/release/deploy）。
2. **agent_meta 不认"AI 使用政策"文体**：`google/benchmark` 是九类里最纯的 agent_meta 样本（通篇规定 AI 能不能参与贡献、必须披露、责任归属），却 0 命中；body 通道只有 `you are` / `your role` / `be concise` / `tone` 这类**人格指令**模式。
