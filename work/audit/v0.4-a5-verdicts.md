## 二、发现 16｜围栏逃逸守卫误伤 shell 注释（**真 bug，v0.1.6 引入的回归**）

v0.1.6 修"围栏里的 `#` 注释被当标题"时加了一条护栏：
**"一段围栏里藏 ≥3 个 markdown 标题时，就不当它是代码块"**（为救 `tempoxyz/mpp` 的畸形嵌套围栏）。

但 shell 脚本的注释块长这样：

```bash
#!/bin/bash

# Use consistent header comment blocks
#==============================================================================
# Script Name
# Description of what it does
#==============================================================================
```

`# Use consistent…` / `# Script Name` / `# Description…` 在 `^#{1,6}\s+` 看来就是 H1——
**≥3 条即触发护栏**，于是整块 bash 被当成 markdown 扫，注释行全部变成章节标题。

实测（558 份全库）：

- **89 份**（16%）文件存在"围栏内的 `#` 注释被当成章节标题"
- **81 份**（15%）**因此产出了类别标签**，例如：
  - `AlexsJones/llmfit`：`# Build` / `# Run TUI` / `# Run CLI mode` → build_test
  - `HKUDS/LightRAG`：`# Install with uv` / `# Install with API support` → environment
  - `Kuberwastaken/claurst`：`# 4. Push (pull --rebase if needed…` → **boundaries**（明显错标）
  - `Dicklesworthstone/destructive_command_guard`：`# Check for compiler errors…` → build_test + gotchas

影响不只是标签：真实章节被这些假标题**切碎**（`Fl·regenerate`、`3. Commit…` 这种标题本身就是代码行）。

> 这是目前全库面最大的结构性问题。修法要同时满足两件事：①shell 里 `#` 注释不算标题；
> ②`mpp` 那种"真标题被包在围栏里"的畸形文件仍要能救出来。倾向判据：**围栏内出现语言特定的
> 注释壳（`#!/`、`#===`、`# ---`）时，一律按代码块处理**；只有围栏内出现的是**带空格的
> 中文/英文短语标题且无注释壳**时才走逃逸分支。
