# C 组（边界件 10 份）判定 · 两道闸门

判据：`is_substantive`（是否实质内容）与 `is_pointer`（是否只是转引用）——这两道闸门决定
558 份里哪 511 份进统计口径。**判错的代价是双向的**：误排除会丢掉真内容（并且把规则的漏标藏起来），
误收录会把空壳算进覆盖率。C 组就是为这两个方向设的。

## 1. 抽出来的 10 份：排除正确 10/10

10 份全是 9–29B 的**单行转引用存根**（内容是 `CLAUDE.md` / `.ai/AGENTS.md` / `.agents/rules/base.md`
/ `.github/agents/pg-toolbelt.md`），`is_substantive=False`，不进口径——**判定正确，0 错**。

## 2. 但 C 组漏了方案里说的另一半（抽样脚本 bug）

`plan-100.md` 写的是「C 边界件 10 = **7 份 `is_pointer` 全取** + 随机 3 份非实质」。
实际 10 份里**一份 `is_pointer` 都没有**，语料库里那 7 份一份都没进 100 份样本。

根因在 `work/audit_sample.py:84`：

```python
ptr_idx = sorted(i for i in df.index if df.at[i, "is_pointer"])
```

`df = substantive(allrows)` 是**已经过滤掉空壳与指针**的 511 基座——在基座里找指针文件，
结果恒为空集。修法：指针池要从 `allrows` 里取（`i for i in allrows.index if allrows.at[i, "is_pointer"]`）。
同一行的 `shell_pool` 用的正是 `allrows.index`，所以只有指针那一半漏了。

## 5. 附带发现：那条回归测试盖不住真实案例

`tests/test_smoke.py::test_known_boundary_short_doc_with_rules` 用的文本是合成版：

```
- FAQs use a `faqItems` frontmatter field. See `billing.mdoc`.
```

注意 **`.mdoc`** ——而真实 `buttondown/docs` 写的是 `See \`billing.md\``，
正是 `POINTER_PAT` 的命中点。所以测试通过、真实文件却落在指针池里。
**教训：闸门类回归必须直接喂真实文件正文**（`data/raw/full/buttondown__docs.md`），不能用合成近似。
