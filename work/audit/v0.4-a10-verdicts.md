## 二、发现 30｜`heading:version` → workflow

全库含 `version` 的标题 **41 个**，多数确实是版本管理：
`Version Management` / `Bump Version` / `Release — Unified Version Bump` / `Release versions` / `Versioning` —— policy 对得上。
但在 `nacos` 上撞了：`## Java Version Targeting`（JDK 版本要求）被判 workflow。
同类边缘例还有 `Build web version (desktop renderer)`（Folo，实为 build_test）。
⇒ 与发现 20（`process`）同族但**precision 高得多（约 8 成）**，不建议删，建议加最小否决：
`version targeting` / `version requirement` / `version compat` 不算 workflow。

## 三、发现 31｜"模块名（文件名）"型标题被前缀命中（归入发现 29）

`AivoClaw` 的 `### Provider Configuration (\`provider-config.ts\`)` 被判 environment，靠的是
`config` **前缀命中 `Configuration`**。这一族标题的通用形态是 `### 某某模块 (\`path/file.ts\`)`，
全库**含反引号或括号且拿到标签的标题共 388 个**（这是族规模，不是错误数）。

- 判定口径：这类标题是**路由到某个模块的说明**，其类别应由正文决定，而不该由标题里的裸词决定。
- 具体到 AivoClaw：4 个模块段（Provider Configuration / Setup Wizard / Config Backup & Recovery /
  Kimi Plugin & Search）都该是 structure，被判成 environment。
- 与发现 29（h1 里的项目名）合流成一条 v0.1.8 建议：**标题通道加一条守卫——标题形如 `X (\`file\`)`
  或 `X (\`dir/\`)` 时，只允许高精度词命中**（`architecture`/`layout`/`gotcha` 这类），
  裸词（`config`/`setup`/`run`/`rule`/`pattern`）一律不算。

## 四、发现 7 / 10 复现｜英文禁令漏标

`nacos` 的 `## Security Vulnerabilities` 整节就是一条禁令：
> Do NOT report security vulnerabilities via GitHub Issues. Use ASRC instead.

词表里的英文禁令只有 `\bnever commit\b` / `\bdo not commit\b` / `\bmust not\b` 三条窄式，
`Do NOT <其他动词>` 全部漏掉。这是发现 7（大写 DO NOT 型）与发现 10/17（英文禁令累积 5 例）的**第 6 例**。
⇒ v0.1.8 的英文禁令一般式（注意 body 通道是 `re.I`，大写式需 `(?-i:DO NOT)` 之类写法）仍是必要项。
