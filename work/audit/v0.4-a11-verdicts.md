## 二、发现 32｜`heading:what is` → overview 的前缀假阳性

全库 `What is…` 标题 11 个，8 个真（`What is VoltAgent?` / `What is DeerFlow` / `What is Pyroscope?` / `What is HAPI?`…），
3 个假：

```
camel        What is in scope (concise summary)   ← 安全模型的范围节
camel        What is out of scope                 ← 同上
contrabass   What is FORBIDDEN                    ← 禁令
```

precision 本身还有 7 成，但**致命处在于 camel 的文件级 overview 完全建立在这两处假阳性上**——
真 overview（`## Project Info`）因为标题里没有词表词而 0 命中。
⇒ 建议：`what is` 只在**标题以问号结尾或后面跟单个名词短语**时算（`What is <Name>?`），
或加否决 `what is (?:in|out of) scope` / `what is forbidden`。

## 三、发现 33｜`heading:requirement` → environment

全库含 `requirement` 的标题 **37 个**，逐条看真属环境/前置条件的只是少数，多数是：
`Performance Requirements`、`PR Requirements`、`Testing Requirements`、`Frontmatter Requirements`、
`Pre-Commit Requirements`、`Merge Requirements`（camel 本批的现场）。
⇒ 与发现 9（`heading:tool`，独撑 33）同族：**"Requirements" 在英文仓库里默认指"要求/验收标准"，不是"依赖"**。
建议：`requirement` 只在 `requirements.txt` / `prerequisite` / `system requirement` 这类形态下算 environment。

## 四、发现 34｜`\bbe concise\b` → agent_meta（6/6 全假）

agent_meta 正文通道里的 `\bbe concise\b`，全库只有 6 处命中，**没有一处是对 AI 说话**：

```
ComfyUI     Documentation and README edits should be concise, factual…
doris       The short summary must be concise and written in imperative…

openai-agents-python  Commit messages should be concise and written in the imperative

```

⇒ **precision 0/6**，且 `openai-agents-python` 的 agent_meta 全靠这一条撑着 ⇒ 建议直接删。
（对照：同族的 `\bdo not (?:praise|flatter|apologize)\b` 语义窄、没被证伪，可留。）

## 五、发现 35｜agent_meta 的"无词可依"黑洞

`openai-agents-python` 提供了一个极端个案：文件 90% 的内容（skill 授权、工作状态三态、评审阈值、GitHub 可粘贴产物规则）
是**明确的 AI 行为规定**，但整篇不出现 `you are`、`AI ... must`、`be concise`（真句）、`agent behavior` 之类词表词，
唯一命中的 `be concise` 还是假的。结果：agent_meta 标签"对"，但理由完全是巧合。

- 这解释了为什么 agent_meta 覆盖率（30.9%）与直觉严重不符：**它的两个主要通道分别是
  `you are`（52 份、precision≈50%）和 `behavior`（21 个标题、precision≈30%）**，
  而**真正"通篇给 agent 定规矩"的文件反而可能 0 命中**。
- v0.1.8**不建议**为此加宽词表（会立刻污染其它类）；建议把它记入 `LIMITATIONS.md`
  作为"规则法的天花板"的第二个量化个案（第一个是发现 19 的散文型标题）。
