## 二、发现 40｜`评审/review` 的定义撞车（产品型仓库）

`## Review…` 型标题全库 **74 个**。大多数是贡献者流程（`Code Review Guidelines`、`Review Focus`、
`PR Reviewers`、`Reviewing`），**按定义（workflow = 分支/提交/PR/评审/发布）标 workflow 是对的**。
但在"产品本身就是做 code review"的仓库里，同一词指的是**功能**：

```
plannotator   ## Plan Review Flow / ## Code Review Flow / ## Since-main default review view
              ## GitButler review invariants / ## Code-review Ask AI context
              ## Review Server (`packages/server/review.ts`)     ← 组件名，最刺眼
              ## Plan Version History                            ← 功能节，靠 heading:version
```

⇒ 这不是"词表错"，是**规则法无法区分"讲评审"和"叫评审的东西"**。
建议记入 `LIMITATIONS.md`（第三类个案：**产品名与流程名同形**），
并在 `TAXONOMY.md` 口径里写明白："review 型标题在无法判断是指贡献者流程还是产品功能时，
若同节内容是 API/数据/组件描述，则不算 workflow"。**不建议**删 `review` 词（74 个里大多数是对的）。

## 三、发现 41｜`agent tool` 的 precision 数据（结清 TAXONOMY.md 的挂账）

v0.1.4 的备注写着：
> 更宽的删除口径（再删 agent tool / prompt / note / skill / behavior / workflow）实测会到 25.2%——
> **未采纳**：那些章节通常是内容型，等 100 份人工核对给出 precision 数据再定。

现在给数据。全库 `agent tool` 型标题只有 **6 个**，**逐个看过，6 个全是"产品里的 agent 工具"文档，不是 AI 行为规定**：

```
Bug Bounty Agent Toolkit — Plugin Guide     Agent Tools        New Agent Tool
WebMCP (browser-agent tools)                Agent Tooling      Agent tool design
```

⇒ **precision 0/6（保守说 ≤1/6）**，与 v0.1.4 已删的 `agent instruction` / `agent guidance` / `ai instruction`
是同一类（**词里没有"这是给 AI 的规矩"这层信息**）。**建议 v0.1.8 删 `agent tool`**。

同批抽查的对照组 `agent note`（12 个标题：`Agent Notes`、`Coding Agent Notes`、`Agent Note: <topic>`…）
**看起来全真**（那些节确实是写给 agent 的备忘录）⇒ **保留**。
即 v0.1.4 那个"更宽删除口径"里，`agent tool` 该删、`agent note` 不该删——两组不是一回事。
