> 目的：把"人与智能体协作"的最长一条真实痕迹抽成**可判断的事实清单**，交给用户判断。
> 方法：**只取机器原始痕迹**（git 时间戳 / 作者字段 / 文件 sha / diff），不取会话正文
> （风控：`~/.hermes` 下任何原始会话文件禁止整段读取，见全局 AGENTS.md）。
> 生成日期：2026-09-11 ｜ 全部命令见文末，可重跑。

## 0. 先说弱点（五条，不能省）

1. **n=1 参与者**。8 个仓库全是同一个人推进。它能支撑"机制存在、机制如何演化"，
   **不能**支撑"普遍规律""比例数字"——与本项目 FINDINGS 发现 15 的稳健性分级同标准。
2. **自我观察偏差**。记录（CODEX.md / MESSAGES.md）是当事人+当事人指挥的智能体写的。
   故本文件**只采信 git 能验证的部分**；文本内容仅作"存在性证据"，不作"事实断言"。
3. **幸存者偏差**。本机留下的都是还在的项目。**同期被放弃、删掉、没进 git 的实践，
   这份痕迹里是零**——这是最大的系统性盲区（见第 6 节 Q1）。
4. **来源性质是"对话形成 + 当事人确认"，属当事人陈述**（2026-09-11 当事人更正）。
   这些文档**不是人独立撰写的**，而是人机对话中成形、经当事人确认后落盘的。
   我无法核实其生成过程（读不到会话正文），故只能按**最低可信档**登记。
   这条同时推翻了本项目此前的"人写 / 机器写"二分法——见 F3 的更正与第 9 节的四档谱。
5. **最厚的一层沉淀不在 git 里**（当事人补充，2026-09-11）：`~/.hermes/skills/` 下有
   160 份技能、其中 77 份由智能体自建，**完全不受版本控制**——没有 diff、没有提交历史，
   只能从 mtime 和策展报告重建。本文件第 1–7 节的方法（"只取 git 可验证的痕迹"）
   **对这一层整体失效**。见第 9 节。

### 8.2 两条通用边界

- **核验方式**：原始仓库不公开，对外只给**指纹**——提交哈希、时间戳、文件行数变化。
  任何人可据此验证"这条时间线存在"，但拿不到内容。**这是本文件对外可用的上限。**
- **引用边界**：S1–S11 一律**只能支持"存在性 / 机制性"论断**，
  不得作为普遍性证据，**不得进入 `FINDINGS.md` 作为独立发现**。
  私有来源产出的结论只能进"假设来源"一节，否则会污染本数据集最值钱的东西——
  "谁都能验"。

### 8.3 来源性质分级（可信度从高到低）

1. **可复核**：公开语料 + 逐行 `file_sha`（仅 S0）
2. **有存证**：git 记录（时间戳 / 作者字段 / diff）——能验证"发生过"，不能验证"为什么"（S1、S2、S7、S10、S11）
3. **当事人陈述**：对话形成的文档，其生成过程无法外部核实（S3–S6、S8、S9）

> 第 3 档不是"不可信"，是"必须写明是谁说的"。把它当成第 1 档用，才是问题。
